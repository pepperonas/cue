# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cue` — a multi-tenant prompt-/todo-queue web app for managing Claude-Code-CLI prompts.
Capture prompts, group by project, work them through a status workflow (Queued →
Running → Done, plus Failed/Archived), and copy them into the CLI with one click.
Deployed at `https://cue.celox.io` behind a reverse proxy. Repo: `pepperonas/cue` — ⚠️ **PUBLIC** (this line said "private" until 0.59.1 and was simply wrong; checked with `gh repo view`). Nothing sensitive lives in the tree — every secret is in the `.env` on the VPS and on the runner Mac — but treat anything committed here as readable by anyone.

Hard constraints: **multi-tenant** — sign in with **Google OAuth**, each user owns their own
projects/prompts (`User` table + `user_id` FK on every owned row), access gated by an
email/domain allowlist. MD3 Expressive design with real spring motion, footer
`© 2026 Martin Pfeffer | celox.io` on every page.

## Commands

```bash
# Backend (from backend/)
uv venv && uv pip install -e ".[dev]"     # setup
uv run uvicorn app.main:app --reload --port 8000   # dev server (set CUE_DEV=1 COOKIE_SECURE=false)
uv run pytest                              # run all tests
uv run pytest tests/test_api.py::test_full_flow    # single test

# Frontend (from frontend/)
pnpm install
pnpm dev                                   # Vite dev server :5173, proxies /api -> :8000
pnpm build                                 # tsc -b && vite build -> dist/
pnpm typecheck
pnpm vitest run                            # frontend unit tests (src/lib only)

# All suites + badge refresh (from the repo root; root package.json)
npm test                                   # backend + runner + frontend, then posttest
npm run update-badges                      # refresh README LOC/test badges (idempotent)

# Full app (prod): one container serves API + built frontend
docker compose up -d --build               # listens on 127.0.0.1:8791
# Auth needs GOOGLE_CLIENT_ID/SECRET + an allowlist in .env (see .env.example).
```

After backend or frontend changes, run `uv run pytest` and `pnpm build` before committing
(or `npm test` from the root to run all three suites — it also refreshes the README badges
via the `posttest` hook).

**Testing conventions:** three suites — `backend/tests/` (pytest, black-box over the HTTP
API with a real tmp SQLite; shared fixtures/helpers in `conftest.py`: `client`, `auth()`,
`make_user()`, `RUNNER_HDR`/`CAPTURE_HDR`), `cue-runner/tests/` (pytest + pytest-asyncio,
fake subprocesses + httpx `MockTransport` + a programmable `FakeApi` for the orchestration
loops in `test_orchestration.py`, no network), `frontend/src/lib/*.test.ts`
(Vitest, only pure lib modules — UI components are deliberately untested). Test behavior,
not implementation; external deps (Google OAuth via monkeypatched `_post_form`/`_get_json`,
subprocesses, browser APIs) are mocked; everything runs offline and deterministically.
Coverage: backend 98 %, runner 90 % (`--cov=app` / `--cov=cue_runner`), **frontend `src/lib` 95 %**
(`vitest --coverage`, `@vitest/coverage-v8`); remaining gaps are defensive except-branches,
`__main__.py`, a few executor cancel branches and — on the frontend — React glue (hooks, the
`api.ts` transport wrappers). **The frontend number is scoped to `src/lib` on purpose**: components
are deliberately untested, so measuring all of `src/` would report a figure nobody intends to raise.
It was added after the unmeasured state hid two real holes — `lib/media.ts` sat at 0 %, and
`boardCollision` (the pointer-based hit testing) had only its construction covered, none of the
rules it exists for. **When logic worth testing is trapped inside a hook, lift it out** rather than
adding a renderer: `media.ts` exports `subscribeToMedia`/`matchMediaOrNull` for exactly that reason,
and `live-sync.ts` exports the whole polling loop as `createChangeLoop` (framework-free, driven in
tests by a stub request plus `vi.useFakeTimers`) so `useLiveSync` is left with nothing but wiring.
**A test that cannot fail is not coverage** — new guards are checked by breaking the code on purpose
and confirming the test goes red. That pass is what showed two of the loop's own tests to be weaker
than they read: `stop()` aborts the in-flight request, so "an answer arriving after stop()" never
reached the `stopped` guard it claimed to cover, and "stops for good" passed with the abort removed
entirely (no new calls either way — the leak is on the server, invisible locally). Both were rewritten
to reach the real thing.
**Six suites test a PROPERTY of the whole surface rather than one call site**, because the bugs they
guard against are the kind nobody introduces on purpose — they are the kind nobody applies a rule to:
`backend/tests/test_tenancy.py` walks every route in the app and fails when one neither scopes to
`current_user_id` nor authenticates a machine nor sits in `UNSCOPED_BY_DESIGN` with a written reason
(a second test deletes stale entries from that list, so a removed endpoint cannot leave a waiver
behind for whatever reuses its path); it also asserts every mutating tenant endpoint carries
`require_csrf`, and sweeps a second account across every owned resource expecting **404, never 403** —
"forbidden" confirms the row exists. `contracts/column-order.json` + `test_ordering_contract.py` +
`order.contract.test.ts` turn the Python/TypeScript ordering mirror from a comment ("change one,
change the other") into something that fails: both languages run the SAME 18 cases, and those cases
additionally run through real SQLite, because the order is stated a THIRD time as `BOARD_ORDER_SQL`;
a stand-in object raises if `display_key` ever reads a field a drag cannot control.
`backend/tests/test_deps_contract.py` holds the two dependency lists — `pyproject.toml` (what uv and
the tests install) and `requirements.txt` (**what the Docker image installs**) — to the same packages
AND the same version floors, after `cryptography` + `anthropic` shipped in only one of them and the
image came up without them: the failure landed at import time in production, after the health check
had already swapped the container. `test_security_tokens.py`
is almost entirely negative — tampered, truncated, cross-signed, expired, cross-purpose — because a
valid signature IS the authorisation here and every happy path keeps working while a broken check
quietly stops checking. `markdown.security.test.ts` parses the rendered output with a real DOM and
asserts no element outside the allowed set and **no attribute at all**, which is what makes leaving
quotes unescaped safe; it also asserts the payload stays READABLE, so nothing is silently swallowed.
**Assert against the DOM, not the string**: escaped inert text legitimately contains `onerror=` and
`javascript:`, so a substring check there fails on correct code.
`scripts/update-badges.mjs` maintains FOUR generated blocks in README.md — the hero (version + LOC, `for-the-badge`, deliberately above everything else), the badge wall (`<!-- badges:dynamic -->`, ~40 badges), the tech stack (`<!-- stack:dynamic -->`, whose VERSIONS are read from `pyproject.toml`/`package.json` — they used to be typed literals like "React 18" and would have gone silently wrong at the next upgrade, because nobody re-reads a badge they wrote themselves) and the test-suite table (`<!-- tests:dynamic -->`). ⚠️ **The generator validates its own relative links before writing**: a badge with a broken one wedges it completely — it runs the backend suite to measure coverage, that suite checks every README link, so it cannot rewrite the file whose state is blocking it (hit while adding the stack block; `relativeLinkTargets` now names the offending target at the point of the mistake). ⚠️ `test_docs.py` strips EVERY generated block when checking that the version is not restated by hand — a hand-maintained list of block names is the same rot the test exists to catch. Historical note, still true of the two original blocks: `scripts/update-badges.mjs` maintains generated blocks in README.md — the badge wall (`<!-- badges:dynamic -->`, 20 badges) and the test-suite table (`<!-- tests:dynamic -->`). Both marker blocks must exist; a missing one **throws** rather than appending, because silently growing a second copy of the badges at the end of the README is worse than a red build. Sources: version (single source = `backend/app/main.py` — only bump main.py, everything else follows), tests total + per suite (`pytest --collect-only` / `vitest list` / `node --test`, never grep `it()`), coverage (`pytest --cov` TOTAL / vitest `All files`, threshold colors), LOC per language incl. test LOC and the test:code ratio, API endpoints (route decorators), DB tables (`table=True`), React components, docs pages. Runs on every `npm test` via posttest; idempotent. ⚠️ **The parsing half lives in `scripts/badges-lib.mjs` and is unit tested** (`scripts/tests/`, `node --test`, dependency-free — the 4th suite): the risky part is not the fetching but the regex over a tool's output, and one that silently stops matching turns every badge into a confident lie. Two of those tests were themselves too weak until mutation-checked — the TOTAL-row test used input a loose `/TOTAL.*?(\d+)%/` also rejects, so it could not tell the anchored pattern from a sloppy one.

## Documentation

Six documents, and the split is deliberate: **`CLAUDE.md` is the working
surface** (dense, gotcha-first, for whoever edits the code), everything under
`docs/` is for someone who has to understand or run the thing.

| File | For |
| --- | --- |
| `README.md` | first contact — features, quickstart, deployment, badges |
| `docs/ARCHITECTURE.md` | how the pieces fit: one process/one port, data model, tenancy, live-sync, the runner |
| `docs/CONFIGURATION.md` | every env var, its default and its effect |
| `docs/API.md` | all 90 endpoints, who may call them, status codes, long-poll |
| `docs/TESTING.md` | the testing method, incl. the mutation rule and the four property-suites |
| `SECURITY.md` | threat boundaries, what is protected how, and what is explicitly NOT claimed |
| `CONTRIBUTING.md` | setup + the rules that have actually prevented bugs here |

⚠️ **`backend/tests/test_docs.py` holds the docs to the code** and is the reason
they can be trusted: every setting `config.py` reads must appear in
`.env.example` AND in `CONFIGURATION.md` (and neither may invent one), every
route decorator must appear in `API.md` (and vice versa), the shipped version
must have a CHANGELOG entry, the CHANGELOG must be unique and newest-first, the
generated README markers must exist as standalone lines, and every relative link
in every doc must resolve. It was written after finding real drift: the README
prose claimed **290 tests while the badges said 1038**, three settings
(`CUE_DEV`, `OPTIMIZE_MAX_RETRIES`, `OPTIMIZE_STALE_GRACE`) were in the code and
in no document at all, the README's backup instructions said `cp` where the ops
script deliberately uses `.backup`, and the code comment on `CUE_DEV` described
it as a harmless client preference when it disables four production guards.

⚠️ Two traps when writing such tests, both hit here: the env-var extraction must
allow a **newline between `get(` and the name** (black wraps long calls, and
`ATTACHMENTS_DIR` sits on its own line — a single-line regex under-reports and
the test becomes decoration); and the marker check must match a **standalone
line**, not a substring, because the README explains its own marker names in
backticked prose and that prose satisfied the `in text` check with the real block
renamed. Both were found by mutation, not by reading.

## Architecture

**One process, one port.** FastAPI mounts the JSON API as a sub-app at `/api` and serves
the built frontend (`STATIC_DIR`, default `static/`) as a SPA for all other paths, with an
`index.html` fallback so client-side state survives hard reloads. In dev the two run
separately and Vite proxies `/api` to `:8000`.

**Backend (`backend/app/`)**
- `main.py` — app assembly, lifespan (`init_db`), security-header + CSP middleware, `/api` mount, SPA static serving (with path-traversal guard).
- `config.py` — env-driven `Settings` (cached). `validate()` fails fast (needs `SECRET_KEY` + `GOOGLE_CLIENT_ID`/`SECRET`) unless `CUE_DEV=1`. `is_email_allowed()` enforces the allowlist (empty lists = closed in prod, open in dev). `google_redirect_uri` derives from `ALLOWED_ORIGIN`.
- `db.py` — SQLite engine; a `connect` event sets `WAL`, `foreign_keys=ON`, `busy_timeout`. `init_db` runs `_migrate()` — idempotent `ALTER TABLE` (PRAGMA-guarded) for additive columns (`bookmarked`, `bookmark_order`, and `user_id` on `prompt`/`project`), since `create_all` only adds missing *tables*, never columns (no Alembic).
- `models.py` — `User` + `Project` + `Prompt` (SQLModel tables). `PromptStatus` enum. Every owned row has a `user_id` FK to `user`; `Prompt.bookmarked`/`bookmark_order` back the bookmarks section; `Prompt.tested` flags whether a **done** prompt's feature was tested. Project name uniqueness is **per user**, not global.
- `schemas.py` — Pydantic request/response models (kept separate from table models). `MeResponse` carries `UserRead`.
- `security.py` — itsdangerous signers: session tokens (payload carries `uid` + the CSRF secret), CSRF double-submit check, and short-lived OAuth-`state` tokens (`issue_oauth_state`/`oauth_state_valid`) to guard the Google redirect. No passwords.
- `deps.py` — `current_session` (401 guard), `current_user_id` (extracts `uid` from the session — inject this into every data router to scope by tenant), `require_csrf` (403 guard + Origin check), `get_client_ip`.
- `routers/` — `auth` (Google OAuth), `projects`, `prompts`, `attachments`, `runs`, `importexport`. **Every data query is filtered by `user_id`; ownership is re-checked on get/update/delete (404 if not owned).**
- **Prompt capture** (`models.CaptureSession/CapturedPrompt`, `routers/capture.py`): every prompt typed in the Claude Code CLI is logged into cue via a `UserPromptSubmit` hook → spool → the cue-runner's forwarder → `POST /api/capture` (Bearer `CAPTURE_TOKEN`, attributed to `OWNER_EMAIL`'s user). Items carry `{session_id, cwd, git_root, prompt, seq}`; the project is derived under `CAPTURE_BASE` (`Settings.capture_project_name`, auto-creates the project): preferred from the hook-reported **git root** relative to the base with `_`-prefixed grouping folders skipped (`_customers/celox/website` → project `celox/website`; an all-underscore root keeps its own name), fallback = first non-`_` `cwd` segment (old hook / no repo / root outside base; `_customers/celox` → `celox`), grouped into a `CaptureSession` per Claude `session_id`, deduped on `(session, seq)`. Owner-facing history: `GET /api/sessions(/{id})` (session detail lists prompts newest-first, `seq` desc), `POST /api/sessions/{id}/prompts/{cp}/promote` (captured → real queued prompt), `DELETE /api/sessions/{id}`. **Multi-tenant:** `/api/capture` resolves the Bearer token to a user — the env `CAPTURE_TOKEN` → `OWNER_EMAIL`, or a per-user `User.capture_token` → that user (with `User.project_base` for derivation). Sessions endpoints + the **Verlauf** tab are per-user (`current_user_id`, not owner-gated); `Settings → Prompt-Capture` lets any user set their base + (re)generate their token. The runner sets `CUE_NO_CAPTURE=1` on its own `claude` execs; its forwarder throttles retry errors. Hook lives in `~/.claude/settings.json` (`python3 …/cue-runner/hooks/capture_hook.py`); runner needs `CAPTURE_TOKEN` in `cue-runner/.env`. All phases done.
- **Send a prompt into a live CLI session** (`models.CliDelivery`, `routers/capture.py`, reverse of capture): the capture hook additionally records each session's terminal context (`ITERM_SESSION_ID`, `TMUX`/`TMUX_PANE` → `CaptureSession.term_program/iterm_session_id/tmux_pane/tmux_socket`, refreshed on every ingest); a session is `deliverable` when a transport is known. Owner-only `POST /api/sessions/{id}/send {text, submit}` enqueues a `CliDelivery` (`queued`); the runner claims it atomically via `GET /api/cli/claim` (guarded by `RUNNER_TOKEN`, mark `sending`), performs it, and reports via `POST /api/cli/{id}/result`; the frontend polls `GET /api/cli/{id}`. **Owner-only** (`require_owner`) because it drives a terminal on the runner's machine, exactly like runs. Runner transport = `cue_runner/deliver.py`: **iTerm2** via `osascript` (AppleScript `write text`, GUID from `ITERM_SESSION_ID`) and **tmux** via `paste-buffer`, both using **bracketed paste** (ESC[200~…ESC[201~) so multi-line prompts land as literal input; then an optional Enter to submit. All ids validated + argv-only (no shell/AppleScript injection). Runner delivery loop polls `GET /api/cli/claim` every `DELIVER_INTERVAL` (1.5 s; `CUE_DELIVER=0` disables). **iTerm2 needs a one-time TCC Automation grant** for the runner's process. Frontend: `SendToSessionDialog` + "An CLI senden" in `DetailSheet` (gated on `canRun`).
- **Run engine** (`models.Run/RunStep/RunLog`, `routers/runs.py`): execute saved prompts through the Claude Code CLI on a Mac **runner** that polls cue. A `Run` is `single` (one step) or `chain` (ordered steps in one Claude session); `RunStep` snapshots the prompt text (reproducible). **User endpoints** (`POST/GET /runs`, `GET /runs/{id}?after_seq=`, `POST /runs/{id}/cancel`, `GET /runs/config`) use cookie auth and are **owner-only** (`require_owner` → `OWNER_EMAIL`; the run executes code on the runner's machine, so it must not be open to other allowlisted users). **Runner endpoints** (`POST /runs/claim`, `/runs/{id}/heartbeat|log`, `/runs/{id}/steps/{idx}/result`, `/runs/{id}/result`) are guarded only by `RUNNER_TOKEN` (`require_runner`, Bearer). Claim is **atomic** (single `UPDATE ... WHERE status='queued' ... RETURNING id`). `project_path` is whitelisted via `Settings.is_path_allowed()` against `ALLOWED_PROJECT_BASES` (string-only on the VPS; the runner re-validates). Chains thread one Claude session; the runner pre-assigns it via `--session-id <uuid>` then `--resume` (CLI v2.1.195 has **no `--cwd`** → set subprocess cwd; **no `--max-turns`** → rely on per-step timeout + `--permission-mode`). Cancel sets `cancel_requested` (running) or `canceled` (queued); the runner learns it from the heartbeat response. The Mac daemon lives in **`cue-runner/`** (own venv/pyproject, PM2-able): asyncio claim-loop, step exec via `create_subprocess_exec` (sets `cwd`, `stdin=DEVNULL` to skip the CLI's stdin wait, parses `stream-json`), heartbeat (also picks up cancel), SIGTERM→SIGKILL cancel, per-step timeout; its own `ALLOWED_BASES` re-validation. `cue-runner/` is **not** deployed to the VPS — it runs on the Mac where `claude` is authenticated. **Frontend** (`RunsView`, `RunDialog`, `state/queries` `useRunConfig/useRuns/useRun/useCreateRun/useCancelRun`): the **Runs** tab + the prompt "Ausführen" action + select-bar "Ausführen" (1 prompt = single, ≥2 = chain) are gated on `useRunConfig` succeeding (owner-only; a 403 hides them, `canRun`). `RunDialog` picks a project base from the whitelist + optional subfolder, model/permission-mode/allowed-tools/bare/skip-permissions/stop-on-error — the last-used settings persist in `localStorage` `cue-run-prefs` and are restored on open (validated against the config whitelists; the **subfolder** deliberately always starts empty); `RunsView` polls (`refetchInterval`) for a live status + log tail, copyable session id, cost, cancel, and re-run. **Hardening (P4):** `runs.reap_stale()` fails runs stuck in claiming/running whose `last_heartbeat` is older than `RUN_STALE_TIMEOUT` (also cleans up runs left in-flight across a backend restart); a `_run_reaper_loop` in the lifespan runs it at startup and every 60 s. The runner heart-beats independently of step progress, so long steps aren't falsely reaped. (P1 backend + P2 runner + P3 frontend + P4 hardening done; P5 = e2e/docs/version + live runner.)
- **Snippet library (Inspector-Rust roundtrip workbench)** (`models.Snippet/SnippetGroup`, `routers/snippets.py`, format contract in **`app/ir_format.py`** — pure parse/build, no DB/FastAPI, tested incl. a golden roundtrip against `tests/fixtures/ir-backup-snippets.json`): import an IR backup JSON → edit/structure in cue (Snippets tab) → export an IR backup that IR's "Settings → Backup & restore → Import" reads. **Write-side invariants:** `version` MUST be 2, timestamps are unix MILLIS, `abbreviation` is IR's merge key (verbatim, trim only), groups travel by NAME (`snippet_categories` carries EMPTY groups + order), `category` is three-valued (`"name"` assign · `""` explicitly ungroup · `null` = leave IR untouched) — cue exports `""` for ungrouped, NEVER `null`; history/notes/totp_entries/settings stay empty. Read side is tolerant (full envelope / snippets-only / legacy `[{abbreviation,body}]` → ungrouped; encrypted backups rejected with a clear message; per-row errors collected, never fatal). Import merges: upsert per `(user_id, abbreviation)` (unique per tenant, enforced in the router like `Project.name`), group get-or-create by name, `category: null` never clobbers a cue-side move. `SnippetGroup` exists only so empty groups + order persist; rename back-fills the denormalized `snippet.group_name` in one txn; NO index on `SnippetGroup.name` (SQLModel's auto name would collide with `snippet.group_name`'s `ix_snippet_group_name`). Export supports `?groups=a,b`. Frontend: `SnippetsView` (dnd-kit with two id namespaces — numeric snippet ids + `sec:<name>` for group headers/droppables), `SnippetEditor` (live duplicate check via `lib/snippets.ts:abbreviationTaken`), grouping helper `lib/snippets.ts:groupSnippets` (vitest-tested; orphaned group names still render). **Versioning (0.17.0, roundtrip since 0.19.0):** `Snippet.version` starts at 1 and bumps ONLY on content changes (abbreviation/title/body); group moves, reorder, bulk-move and no-op saves don't bump. Since 0.19.0 the version IS in the envelope as an ADDITIVE per-snippet field (older IR ignores unknown keys); shared cue<->IR merge rule on import: content differs -> `max(incoming, local+1)`, identical -> `max(incoming, local)`, missing/0 -> 1 — re-importing cue's own export is a no-op and both sides converge. UX (0.15.1): search field over abbreviation/title/body (`lib/snippets.ts:filterSnippets`, hides empty groups while searching), visible select mode with row checkboxes + per-group select-all (Cmd/Ctrl+click still toggles), snippets sort ALPHABETICALLY by abbreviation within each group (0.21.1, matching IR — `groupSnippets` ignores `sort_order`, row drag/reorder removed on purpose; group moves go through the editor's group field or bulk-move; group HEADERS stay drag-sortable, disabled while searching/selecting), copy-body button per row. Group create/rename go through `InputDialog` (inline duplicate validation); snippet deletes (editor + bulk) confirm via `Confirm` with a merge-semantics reminder. The UI permanently hints that IR imports MERGE: cue-side deletions/renames don't delete in IR.
- **Automatic IR sync (0.21.0)** (`routers/sync.py`, `models.SnippetTombstone`, per-user `User.snippet_sync_token`/`sync_ungrouped`/`snippet_sync_last`, `SnippetGroup.synced`): IR polls `GET /api/sync/snippets` (Bearer sync token) and pushes back via POST — cue never reaches out. **Scope is managed ONLY in cue** (☁️ `ToggleIconButton` in each group header + on „Ohne Gruppe"; token in Settings → Snippet-Sync). Sync merge (deliberately different from the manual-import merge): incoming.version > local → adopt content; equal+identical → no-op; equal+different → cue wins; lower → keep local. **Grouping is NOT version-gated — cue is the organizational master** (IR adopts cue's grouping on tie, cue ignores incoming categories for existing snippets). **Tombstones** (`snippet_tombstone`, 90-d TTL, pruned in the pull): every delete/bulk-delete/abbreviation-rename records `{abbreviation, version}` (helpers `record_tombstone`/`resurrect_floor` in `routers/snippets.py`); a tombstone deletes the peer copy only if `peer.version <= tombstone.version`, and (re)creation over a tombstone starts at `tombstone.version + 1` (`resurrect_floor` in create/update/import/sync) — otherwise the next cycle would re-delete it. `record_tombstone` refreshes `deleted_at` only when the version INCREASES (peers echo tombstones back every cycle; refreshing unconditionally would keep them alive past the TTL). The IR counterpart lives in inspector-rust `core/rust-lib/src/sync.rs` (worker thread, 60 s + wake after every snippet mutation, `snippets-synced` Tauri event → UI reload); wire format = `SyncSnippetItem`/`SyncTombstoneItem` field names, do not rename them casually.
- **Central tag vocabulary (0.25.0)** (`models.Tag`/`PromptTag`, `app/tags/`, `routers/tags.py`): tags became a first-class entity instead of comma strings. `tag` holds identity, display spelling, `name_ci` (the lower-cased **uniqueness key per tenant** — that is what makes `Feature` and `feature` one tag), `source` (`user`/`system`) and `last_used_at`; `prompt_tag` is the **source of truth** for assignments. **`Prompt.tags` survives as a denormalized comma cache** with exactly ONE writer (`TagService`) — same pattern as `Snippet.group_name`, which keeps list/search/export/clients unchanged; `rebuild_cache()` is the repair hatch and is covered by a test. Layering: router (HTTP) → `service.py` (normalize, get-or-create, rename/merge, delete/replace, backfill) → `repository.py` (SQL + usage aggregation via one grouped join, no stored counter that could drift). **Rename onto an existing tag MERGES** (assignments move, duplicates drop, the loser row disappears); **delete** optionally re-points assignments to another tag (`?replace_with=`). **Every** prompt write path (create/update/duplicate/merge) goes through `TagService.set_for_prompt`; stats read the tag tables instead of re-parsing strings. **Migration:** `db._migrate_tags()` runs `backfill_from_strings()` per tenant on startup — idempotent (prompts that already have links are skipped), marks migrated tags `source=system` and backdates `created_at` to the prompt that introduced them (14 tags / 165 assignments in production). Frontend: `TagsView` (Tags tab: search, sort, usage, provenance, rename, delete-with-impact-preview), `lib/tags.ts:rankSuggestions` (exact > prefix > word-start > substring, then usage, then recency — unit tested) fed by `mergeSuggestionPool(vocabulary, DEV_TAGS)`, so the ~1.100-entry catalogue stays a static file and only materializes as a row once used. **Gotcha:** deleting a prompt now needs `_detach_references()` + an explicit `session.flush()` — without an ORM relationship SQLAlchemy has no delete ordering, and `foreign_keys=ON` rejected the parent DELETE (that was a live 500 for optimized prompts).
- ⚠️ **The backend has TWO dependency lists (0.54.1)**: `pyproject.toml` for `uv`/the test suite and `backend/requirements.txt` — which is what the **Docker image installs**. Adding a package to only one produces a green local suite and an image that cannot import; the build succeeds, the health gate fires only after the swap, and production answers 502 (that is not hypothetical, it happened with `cryptography`). `tests/test_deps_contract.py` now pins the two lists to each other (same packages, same version floors), and `ops/deploy.sh` imports `app.main` in a throwaway container BEFORE touching the running one.

- **Prompt optimization (0.23.0)** (`app/optimization/`, `routers/optimize.py`, executor in `cue-runner/cue_runner/optimize/`): rewrite a saved prompt with the **Claude Code CLI**. Config lives ONLY in `Settings` (`OPTIMIZE_ENABLED/PROVIDER/MODEL/TIMEOUT/MAX_CHARS/MAX_RETRIES/STALE_GRACE`). **`OPTIMIZE_MODEL` must stay SET** (prod: `opus`): empty means no `--model` reaches the CLI, so the optimizer inherits whatever the runner Mac's Claude Code is currently set to — a `/model` there silently changes what rewrites the prompts, and the history then records whichever model happened to be active that day. - **Activity log + statistics (0.22.0)** (`models.PromptEvent`, `app/events.py`, `app/stats.py`, `routers/stats.py`): the **Statistiken** tab is fed by an append-only `prompt_event` log — one row per created/updated/status_changed/deleted prompt, written ONLY through `events.record()` (called from `prompts.py`, `runs.py`, `importexport.py`). It carries `user_id`, `prompt_id`, a `project_id`/`status`/`body_len` snapshot and `at`, and deliberately has **no FK on `prompt`** (the log must outlive the row — that's the whole point of the `deleted` event, and `foreign_keys=ON` would block the delete). `db._seed_prompt_events()` back-fills a plausible history from `created_at`/`ran_at`/`updated_at` on first migration (approximate; pre-migration deletions are unrecoverable); `events.prune()` drops rows past `RETENTION_DAYS` (730) from the daily GC loop in the lifespan. **`app/stats.py` is the single aggregation service** — FastAPI-free, so it is unit-testable and reusable for future exports/digests: `resolve_range()` turns a preset (`today/yesterday/7d/30d/90d/year/last_year/all/custom`) into a `TimeRange` (plus the equally long previous window for every delta), `pick_granularity()` coarsens hour→day→week→month with the span, `bucket_starts()` produces gap-free axes, and one `_*_section()` per domain (prompts/projects/tags/activity/ai) builds the payload. **Timezone:** the client sends its IANA zone (`?tz=Europe/Berlin`) and ALL bucketing happens in it — aggregating in UTC would file late-evening work under the wrong day and shift the "busiest hour". **Point-in-time facts** (status distribution, backlog, lengths) read live `prompt` rows, **time-sliced facts** read the event log. Results are cached per `(user, version, range, tz)` with a 120 s TTL; `events.record()` calls `stats.invalidate(uid)`, so a write is reflected immediately without polling. Always normalise timestamps through `_local()` before subtracting — rows from SQLite come back naive while freshly written ones are still aware, and mixing them raises (regression-tested).
- **Attachments (screenshots)**: `Attachment` table (`user_id`, nullable `prompt_id`, stored `filename`, `original_name`, `content_type`, `size`). Files live in `ATTACHMENTS_DIR` (set to `/data/attachments` in prod so they persist on the volume). `routers/attachments.py`: `POST /attachments` (multipart, image-only, ≤`MAX_ATTACHMENT_BYTES`) returns `{id,url,name,...}` with `prompt_id=null` (pending); `GET /attachments/{id}` serves the file (ownership-checked, not static); `DELETE /attachments/{id}`. Prompts associate them via `attachment_ids` on create/update (`_attach`), and `PromptRead.attachments` is populated by `_reads()`/`_read()` in `prompts.py` (batch-loaded). `delete_prompt` purges files; `merge` reassigns source screenshots to the merged prompt when originals are deleted. **Auto-expiry**: `attachments.purge_expired()` deletes attachments older than `ATTACHMENT_TTL_DAYS` (30); a daily background task (`_attachment_gc_loop` in `main.py`'s lifespan) runs it. The Composer shows a dismissible inline notice about the 30-day deletion (`localStorage` `cue-hide-attach-notice`). **Client-side re-encode (0.38.0)** (`lib/image-compress.ts`): every image is re-encoded to **WebP q0.85, longest edge ≤ 2048** in the browser before upload — a 2400×1422 screenshot goes 189 KB → 44 KB (4.3×; Retina PNGs with gradients/photos land nearer 10–30×), the bytes never travel, and the server needs no image library. Four guards, each measured: **GIFs are skipped** (a canvas keeps one frame, so re-encoding would silently drop the animation), the result is kept **only if it is really `image/webp`** (`canvas.toBlob` falls back to PNG *without an error* when it cannot encode the type — that PNG measured 307 KB against a 193 KB source, i.e. the "optimization" grows the file 1.6×), **only if it is smaller** (an already-compressed source can come back bigger), and any failure returns the original — a failed optimization must never cost the user their screenshot. Bigger sources become uploadable, since `MAX_ATTACHMENT_BYTES` is now checked against the compressed file. The pure rules (`shouldCompress`/`targetSize`/`keepEncoded`/`webpName`) are unit-tested; `webpName` strips only the LAST extension because real screenshot names carry dots (`… um 22.15.30.png`). **Feedback on paste (0.38.0)**: the screenshots field is the last one in the dialog, so pasting into the prompt text changed nothing anywhere near the cursor — the upload worked and looked like it had not (production had zero attachments ever). `uploadFiles` now scrolls the field into view (`block: 'nearest'`, so pasting mid-sentence doesn't throw the text out of view) and toasts the stored size.

**Auth (Google OAuth, Authorization Code flow)** — `routers/auth.py`:
- `GET /auth/google/login` → signs a `state`, sets it as a `SameSite=Lax` cookie (must survive Google's top-level redirect back), 302s to Google's consent screen.
- `GET /auth/google/callback` → validates `state` vs the cookie, exchanges the `code` for an access token (`oauth2.googleapis.com/token`, with the client secret), fetches the profile (`openidconnect.googleapis.com/v1/userinfo`). Both calls are stdlib `urllib` over TLS, so no id-token signature check and **no extra runtime dependency**. Rejects unverified emails and anyone failing the allowlist. Upserts the `User` by `google_sub`, issues the session, and — for `OWNER_EMAIL`'s first login — claims all `user_id IS NULL` rows (the original single-user data).
- `GET /auth/me` → `{authenticated, csrf_token, user}`. `POST /auth/logout` clears cookies.
- The session cookie stays `SameSite=Strict`; only the transient `state` cookie is `Lax`. Session salt is `v2` (carries `uid`), so old single-user sessions are invalidated.

- **Prompt age on every card (0.41.0)** (`Prompt.edited_at`, `lib/relative-time.ts`, `lib/clock.ts`, `components/RelativeTime.tsx`): each prompt shows how old it is — "gerade eben", "vor 7 Minuten", "vor 3 Stunden" — thresholds taken from day.js/moment, which are tuned to change at moments that read as natural. **The timestamp is `edited_at`, NOT `updated_at`**: the latter moves on every write, and in production it sat more than a minute past the last real content change on **221 of 271 prompts (49 % by more than a day)** because a drag, a status change or a "getestet" tick all bump it — a card announcing "gerade eben" because someone reordered a column is worse than no timestamp at all. `updated_at` has to keep that meaning: `app/changes.py` builds the live-sync fingerprint from `max(updated_at)`, so a status change that stopped bumping it would go invisible on the user's other devices. **`events.record()` is the single writer of `edited_at`** — the activity log and the column answer the same question ("when was this content last written"), so stamping it there, from the same instant as the event, is what stops them drifting apart; `_CONTENT_EVENTS` is the one definition, and applying an optimization is covered by it for free because that path already records an `updated` event. Migration backfills existing rows with **`created_at`, deliberately erring OLD**: the obvious `updated_at` is exactly the drift the column exists to avoid, and the activity log is no better — most of its `updated` rows ARE that drift, copied in by `_seed_prompt_events`, with nothing in the data to tell a seeded row from a real one. **One shared clock** (`lib/clock.ts`) drives every label: one timer instead of one per card, started on the first subscriber and stopped with the last (so Settings and the statistics tab run no timer at all), and components subscribe to the STRING rather than to the time, so React bails out wherever the wording did not move on (measured: 1 of 21 possible re-renders across three ticks). A hidden tab has its timers throttled to about once a minute and a bfcache-restored page has them frozen, so `visibilitychange`/`pageshow`/`online` resynchronise immediately — the same three events `useLiveSync` treats as "conditions changed". On the card, age and action icons are ONE block (`.card-end`) pinned to the bottom right so the number keeps its place however many tags wrapped above it; it must keep `flex-wrap: wrap`, or on a phone the six action buttons plus the age push the copy button off the card. An edited prompt carries a pencil, because a months-old prompt reading "vor 5 Minuten" otherwise looks brand new.
- **Every timestamp leaves the API zoned (0.41.0)** (`schemas.Utc`): SQLite hands rows back **naive** while a freshly written row is still **aware**, so one and the same response carried both `...839915` and `...997876Z`. A JSON date-time without a zone designator is **local time** to every browser (ES2015+), i.e. two hours off in Berlin — the detail sheet had been showing shifted times all along, and the relative ages would have reported everything younger than the offset as "gerade eben" forever. All 28 timestamp fields are `Utc = Annotated[datetime, AfterValidator(_as_utc)]`, normalised on validation (not serialization) so the value is aware everywhere the model is used and Pydantic emits the `Z` by itself. `tests/test_wire_time.py` sweeps the whole schema module — unwrapping `X | None` **and** `Annotated`, because an optional timestamp is the one that slips past a top-level check — and fails on any bare `datetime`; a second test asserts the sweep actually found fields, so it cannot pass by looking at nothing. The client parser stays defensive anyway (`parseTimestamp` appends the `Z` when there is no designator): a response the service worker cached before this change still has none.
- **Cross-device live updates (0.39.0)** (`app/changes.py`, `routers/changes.py`, `lib/live-sync.ts`, `state/live-sync.ts`): two browsers on the same account used to be two islands — a prompt added on the phone stayed invisible on the desktop until someone reloaded. Now every client parks ONE long poll on `GET /api/changes?since=<cursor>&wait=25`, which answers within ~1 s of anything changing (measured: 0,18 s) and otherwise costs nothing. The cursor is a **fingerprint, not a revision counter**: a counter is O(1) to read and drifts silently the first time someone adds a write path and forgets to bump it, whereas a fingerprint is DERIVED from the data, so there is nothing to forget. Per entity (`prompts/projects/tags/snippets/sessions`), so a snippet edit doesn't make three other views refetch. Two shapes: `(count, max id, max updated_at)` where a mutation timestamp exists — three indexed aggregates that catch create, edit, move and delete — and a **digest over the mutable columns** for the two small tables that have none (`project`, `snippet_group`); a project rename is exactly the case `max(updated_at)` would sleep through. `changed()` treats an entity missing from the cursor as changed, so an unparseable cursor means "refetch once", never an error — a client on an older build must not get stuck. **The endpoint takes no `Depends(get_session)`** (same rule as the runner claims, same reason: five pooled connections, and browsers park these several at a time); it authenticates from the signed cookie alone and re-checks approval inside every attempt, which also means revoking approval ends a parked poll on the next tick. Client side the loop itself is **framework-free** (`lib/live-sync.ts:createChangeLoop`; `state/live-sync.ts:useLiveSync` is only the wiring to React Query and to the three events that mean "conditions changed" — `visibilitychange`/`online`/`pageshow`), so all of it is unit-tested: which request carries a cursor and which does not, that a failure never advances the cursor, that a hidden tab drops its parked request, and that no combination of wake-ups can start a second loop beside the first. `INVALIDATIONS` maps an entity to the query keys it really affects — deliberately not 1:1 (a tag rename rewrites the tag strings cached on every prompt without touching their timestamps; the stats are aggregated from prompts+projects+tags) — and the loop **stops while the tab is hidden** (a phone in a pocket would hold a socket for an hour) and catches up in one request on `visibilitychange`/`online`/`pageshow`, because the server checks once before it starts waiting. Failures back off 1→30 s, and coming back online cuts the backoff short instead of waiting it out. **Your own writes echo back** (one extra GET per mutation): recognising them would mean threading a client id through every write path, and the refetch is cheap and self-correcting.

The overlay paints nothing where the user's own text is (`.ghost-typed { color: transparent }`) and carries no background, so the input keeps its fill and the caret shows through; `.ghost-layer` mirrors `.input:focus` geometry exactly (11/13 px padding, 2 px border, `box-sizing: border-box`), which fits both fields because both are `.input`. `ready` is false during an IME composition, whenever the caret is not at the end, and once the value outgrows the field — a scrolled input drifts out of register and a misaligned ghost is worse than none. `lib/tags.ts:inlineCompletion` derives the tag field's grey text; its prefix test is deliberately **case-sensitive**, because "Sec" + "urity" would render "Security" while `→` commits the catalogue's "security", and ghost text that lies is worse than none.
- `lib/title-complete.ts` + `components/GhostInput.tsx` — **word-by-word title completion.** The field shows the next word as inert grey text behind the caret; **Enter takes exactly one word**, and because accepting appends a trailing space the following word is proposed at once — that is what makes it chain. `→` at the end of the field does the same (fish/zsh autosuggest); **Tab deliberately stays focus navigation** (a form field is not an editor, and stealing Tab strands keyboard users in the dialog); Escape dismisses the suggestion **without closing the dialog** (`e.stopPropagation()` — otherwise `useBackDismiss` closes the composer on the first press). The corpus is the user's OWN previous titles via `usePrompts` (React Query dedupes with the board's call, so no extra request): measured on the live data, 94 of 291 titles are exactly two words and the vocabulary repeats hard, which is precisely what a generic word list cannot predict. **The thresholds are measured, not chosen** (leave-one-out over the same corpus): a next-word guess from context alone is 20 % correct and **2 % on an empty field**, while completing the word being typed runs 25 % / 36 % / **51 %** at 1 / 2 / 3 typed characters. Hence `MIN_PREFIX = 2` (which also keeps an empty field silent — there is nothing to complete) and `MIN_SUPPORT = 2` for whole-word prediction (requiring it cut two thirds of the offers while precision held: the discarded ones came from contexts seen exactly once). A wrong ghost costs nothing — it vanishes on the next keystroke — and that asymmetry is what makes a 36 %-correct suggestion worth showing. ⚠️ **The value is never touched until the user accepts**, so what the field holds is always what they typed; the ghost is an aligned overlay (`.ghost-layer`, geometry mirroring `.input:focus` — 11/13 px padding, 2 px border, `box-sizing: border-box`) that paints **nothing** where the real text is (`.ghost-typed { color: transparent }`) and carries no background, so the input keeps its fill and the caret shows through. It hides itself when the value outgrows the field (`scrollWidth > clientWidth`), because a scrolled input drifts out of register with the overlay. Measured contrast of the suggestion: **4.58:1 light / 6.94:1 dark**. Dismissal is stored as the VALUE it applied to, not a boolean — no effect has to reset it and the two can never disagree.
- `lib/tag-rules.ts` — **tags derived from the title.** Every rule was measured against the live corpus as lift over the base rate, and that measurement is the whole reason for the two tiers: `doku`→documentation 86 % (**×28.3**), `animier|*animation`→animation 82 % (×8.2), `fix|fehler|bug`→bugfix 75 % (×4.8), `mobil|s24|iphone`→mobile (×38.5) are written automatically; `optimier`→optimization is only ×1.8 — the single most common word in the corpus and still barely above chance — and `button|icon|menü`→gui has **no lift at all** (the `gui` tag IS used for visual work, but no keyword predicts it), so those are offered in the menu and never written. A wrong tag written without asking is worse than no tag. `AUTO_TAG_LIMIT = 2`, because 208 of 231 tagged prompts carry one or two. Stems match at a word start via an explicit separator class, **not `\b`** (ASCII `\b` mishandles umlauts: `\büber` never matches "übersetzung"); a leading `*` allows a stem inside a word, which German compounds need ("hintergrundanimation" is one word in the corpus). Rules with no corpus support (performance, accessibility, i18n, refactor) are dictionary equivalences and are marked as such. A test pins that every rule target exists in `DEV_TAGS`.
- `components/TagInput.tsx` + `lib/tag-keys.ts` — comma-separated tag field with type-ahead. Completion targets the token after the last comma. **Two ways to end a tag, and they mean different things (0.46.0)**: `→`/`Tab` take the **suggestion** (the grey inline completion, or the highlighted row), `Enter`/`Space`/`,` take **what was typed, verbatim**. Before this, Enter took the suggestion — so writing your own word that the catalogue half-matched meant deleting what the field had just done for you. `↑/↓` navigate, click commits, `Esc` closes the list. After either commit the field is ready for the next tag and the menu re-opens, now ranked by co-occurrence with the tag just added. ⚠️ **The suggestion keys only fire while a token is actually being TYPED**: with an empty token the menu still lists tags, and binding `Tab` there traps the keyboard in the field — every commit re-opens the menu, so no press would ever move focus on. ⚠️ **Space is a separator here, never a character** — checked rather than assumed: across 291 prompts and 20 tags not one tag token contains a space (single-token, hyphenated). Stray separators with nothing to end are swallowed so empty segments cannot pile up. ⚠️ **Escape used to close the whole composer** (the global handler in `App.tsx` runs its Escape branch *before* the editable-target check, and the field never called `stopPropagation`); it now closes the list first, the dialog on the second press. The decision table lives in `lib/tag-keys.ts` as a pure function because it IS the feature — the trap risk, the Cmd+Enter passthrough and the Escape scoping are not observable from a rendered component without a browser; the component only carries the result out. The Composer feeds it a pool of tags already used across prompts (via `usePrompts`) first, then `DEV_TAGS`, deduped case-insensitively. The suggestion list **flips upward** (`.tag-suggest.up`, decided from the input's viewport rect in `recalcDirection`) when there isn't room below — the tag field is the dialog's last field, so a downward menu would otherwise cover the "Anlegen"/"Abbrechen" action buttons. (A sticky action footer was tried and rejected: pinning it to the sheet bottom made it overlap the focused tag input.) **Tags are deduplicated case-insensitively per prompt**: `commit()` won't add a tag the prompt already has, and `normalizeTags`/`dedupeTags` (`lib/tags.ts`) dedup on Composer save + on `PromptCard` render, so a tag can never appear twice on one prompt (kept as a shared helper, first spelling wins). **Ranking follows what the prompt implies (0.45.0)**: `rankSuggestions` takes a `RankContext` of `derived` (tags the title points at, ✨ "Passt zum Titel") and `related` (`relatedTags` — tags that co-occur with the ones already picked, computed from the prompts the client already holds, 🔗 "Wird oft zusammen verwendet"). ⚠️ **Match quality stays the FIRST sort key**: typing "sec" must offer `security` however loudly the title says something else — context only decides between candidates the query ranks equally, which with an empty query is all of them, and that is exactly the moment the menu has nothing else to go on. Measured effect on the live vocabulary: for the title "stats ansicht animieren" the menu leads with `gui` (15 uses) above `improvement` (94 uses). ⚠️ A test that only checked "typing beats context" with a context tag the query **filters out entirely** cannot fail — the discriminating case needs both candidates to survive the filter at different match ranks (`animation` by prefix vs `enhancement` by substring for the query "an").

## Conventions & gotchas

- **No horizontal scroll / mobile**: the board grid uses `repeat(3, minmax(0, 1fr))` (plain `1fr` columns refuse to shrink below a long unbreakable token and blow out the page width); `.column` has `min-width: 0`; card title/preview use `overflow-wrap: anywhere`; `html, body { overflow-x: hidden }` is a final guard. Under 640px the topbar collapses to icon-only tabs (`.tab-label` hidden, brand logo only); the `.tabs` pill additionally SCROLLS horizontally (hidden scrollbar, `flex: 1 1 auto; min-width: 0`) so brand + theme/settings icons always stay on-screen — the shortcuts button is hidden there (`.hide-mobile`), the `.topbar-spacer` collapses, and the `.select-bar` wraps.
- **Dialog scroll**: `DetailSheet` (`.sheet--detail`) and `Composer` (`.sheet--composer`) both clip the sheet (`overflow: hidden`) and scroll only their inner wrapper (`.detail-scroll` / `.composer-scroll`, `flex: 1 1 auto; min-height: 0; overflow-y: auto`) while the header and action footer stay fixed (`.sheet--X > * { flex: none }`). **Keep the pinned parts small and bounded** — a tall element outside the scroll wrapper is clipped by `overflow: hidden` with no way to reach it (that was the optimization panel until 0.37.0); in `DetailSheet` only the header, the pinned decision bar and `.row-end` stay put, badges/status chips/copy button/panel/content all scroll. Ordering the busy projects among themselves still happens in the **Projekte** tab, which is deliberately NOT count-sorted (it is the editor). Draggability follows the data live: finishing a project's last open prompt makes its chip draggable without a reload. ⚠️ The sortable chips deliberately get **no `touch-action: none`**, although a drag handle normally needs it — on a phone this row is a horizontal scroller and taking the pan gesture away would make the later projects unreachable; the TouchSensor's press delay separates a swipe from a drag instead. ⚠️ `withReorderedTail` refuses a tail whose ids it cannot all place (a project deleted mid-drag): without that guard a *leading* unknown id shifts every following write by one and one project is duplicated while another disappears — a trailing one happens to be harmless, which is why the test pins all three positions. The unit tests give the fixture ids that run AGAINST the manual order, because with ids 1..n in order a tiebreak of `a.id - b.id` passes every case while ignoring the user's drag entirely (it survived the first mutation round).

- **Static caching (0.37.1)**: `main.cache_control_for()` in the same middleware — `/assets/*` (Vite content-hashes them) `public, max-age=31536000, immutable`, **everything else static `no-cache`**, `/api` untouched. Without any `Cache-Control` browsers fall back to **heuristic freshness** (a fraction of the age since `Last-Modified`), so after a deploy they kept serving the previous shell while its hashed chunks were already gone: 404 on `index-*.js`/`StatsView-*.js` plus „Refused to apply style … MIME type ('application/json')" — that MIME is the 404 body. An ETag does not save it; a heuristically fresh response is never revalidated. The shell, `sw.js`, `manifest.webmanifest` and `boot.js` are exactly the files that must always revalidate. Headers alone cannot fix a tab that was **already open** across a deploy — its shell predates the change — so `lib/lazy-chunk.ts` (`withChunkRecovery`, wraps the `StatsView` lazy import) reloads **once** on a failed dynamic import and re-arms only after a load succeeds, so a genuinely broken chunk can't loop.

CSP allows Google Fonts + inline styles (needed for runtime dynamic-color vars). **`script-src 'self'` means no inline scripts** — the pre-paint theme snippet lived inline in `index.html` and was therefore blocked (silently, apart from a console violation) ever since the CSP landed, so light-theme users got a dark flash on every cold load. Anything that must run before React mounts goes in that file, never inline.

## Deployment (live: cue.celox.io on VPS 69.62.121.168)

- Code at `/opt/cue` (rsync'd, no git clone). Container `cue` via `docker compose`, binds `127.0.0.1:8791`. nginx block `/etc/nginx/sites-enabled/cue.celox.io` (certbot-managed cert + HTTP→HTTPS redirect). Update: `rsync ./ root@69.62.121.168:/opt/cue/` then `ssh ... 'cd /opt/cue && docker compose up -d --build'`.
- **Frontend Docker stage pins pnpm@10.2.1** (`corepack prepare pnpm@10.2.1 --activate`); bare `corepack enable` pulls pnpm 11.x which needs Node 22+ and crashes on the Node 20 base.
- **`$$`-escape gotcha**: docker compose interpolates `env_file`, so any literal `$` in an `.env` value must be doubled to `$$` (relevant if a Google secret ever contains `$`). Running uvicorn directly uses values verbatim.
- **Deploy** (`ops/deploy.sh`, run on the VPS after the rsync): builds first — a broken build therefore leaves production untouched — then `docker compose up -d --wait`, which returns only once the container reports HEALTHY, and finally re-checks `/api/health` itself. **The container swap closes the port for ~4 s** (measured at the socket, 21 failed probes at 0.2 s spacing); that is the recreate itself and nothing in nginx can retry it away — `proxy_next_upstream` needs a second peer to fall over to, and a graceful-shutdown cap doesn't help either (both tried and measured). Two containers side by side would remove it and would put two processes through `init_db()`'s migrations at once, which is a poor trade for four seconds. So the window is made HONEST instead: nginx serves `deploy/maintenance.html` for 502/503/504 on page requests (`error_page … @restarting` **without** `=`, so the real status survives — with `=` the page would be labelled 200 and lie to crawlers and monitors), the page polls `/api/health` and reloads itself, and `/api/` keeps returning a bare status code because the client parses JSON and would choke on HTML. Install once: `scp deploy/maintenance.html root@host:/var/www/cue-maintenance.html`.
- **Nightly backup (`ops/`)**: `cue-backup.timer` → `cue-backup.service` → `/usr/local/bin/cue-backup.sh`, 03:50 (after the host's other backups), `Persistent=true`, 30-day rotation into `/var/backups/cue/`. Takes the DB with **`sqlite3 .backup`, never `cp`** — a copy is not atomic, and cue's WAL holds committed transactions the main file does not have yet (4.4 MB against a 4.2 MB database; measured once it happened to be current, so the naive copy is a silent risk rather than a certain loss). The screenshot attachments travel in a second archive, because the DB rows reference those files by name. Every run **verifies the copy with `PRAGMA integrity_check` and discards it on failure** — a corrupt generation that rotation later counts as valid hides the gap it creates. The units live in `ops/` in the repo, not only on the server; install with `scp ops/cue-backup.sh /usr/local/bin/`, `scp ops/cue-backup.{service,timer} /etc/systemd/system/`, `systemctl enable --now cue-backup.timer`. **Restore instructions are in the script header** — including deleting the stale `-wal`/`-shm`, which belong to the REPLACED database and would otherwise be applied to the restored one. Still on-host only; an off-site copy would need a destination + credentials and is open. Note: three ad-hoc `cue-backup-pre-*.db` snapshots sit inside the data volume itself (same disk as the original, so not backups).
